AntSDR E200 — O4 firmware setup over COM7 (115200, 8N1)
=========================================================

1. Open serial terminal on COM7
   - PuTTY: Serial, COM7, 115200
   - Or: python -m serial.tools.miniterm COM7 115200

2. Boot E200 (power cycle). Press any key if boot stops for input.
   Login: root
   Password: 1          (O4 firmware — legacy was abawavearm)

3. Verify O4 firmware (must see drone_dji_rid_decode, NOT done_dji_release):
     ps | grep drone
   Expected: drone_dji_rid_decode, droneangle.sh

4. Check current network env:
     fw_printenv | grep -E 'ipaddr|tcp_|api_host|request_time|gain|device'

5. Set env (replace 192.168.1.9 with YOUR PC Ethernet IP from ipconfig):
     fw_setenv ipaddr_eth 192.168.1.10
     fw_setenv tcp_serverip 192.168.1.9
     fw_setenv tcp_serverport 52002
     fw_setenv api_host 192.168.1.9
     fw_setenv request_time 1
     fw_setenv gain_mode fast_attack
     fw_setenv device_mode auto
     reboot

6. On Windows PC — allow firewall for Python on ports 80 and 52002.

7. Run host tools (from antsdr_dji_droneid folder):
     python hex_logger.py
     python dji_receiver.py -d --mode new --listen-port 52002

8. Test connectivity from PC:
     ping 192.168.1.10

9. With O4 drone powered (motors on), you should see:
   - hex_logger:  HEX (... chars): ...
   - dji_receiver: dji_O,... CSV lines on port 52002
   - File: o4_encrypted_hex.log

Troubleshooting
---------------
- Still see done_dji_release → wrong firmware; re-flash build_sdimg_drone_o4.zip
- No hex → wrong api_host IP, firewall blocking port 80, or no O4 drone in range
- No CSV on 52002 → wrong tcp_serverip / tcp_serverport, or E200 not on Ethernet
- COM7 works but no data → normal; data path is Ethernet, not USB serial
